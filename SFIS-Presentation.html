Problem Statement

Introduction

Universities collect thousands of feedback entries per semester. Without an automated system, critical student complaints get buried, ignored, or addressed too late.

Key Pain Points in Traditional Feedback Systems

  • No automatic classification — every entry must be manually read and routed to the right department
  • Subjective urgency assessment — severity is judged inconsistently across different staff members
  • Delayed escalation — critical safety issues may sit unresolved for days before reaching the right person
  • No trend visibility — institutions cannot see whether complaints about a specific category are increasing
  • Data silos — feedback stored in spreadsheets cannot be searched, filtered, or reported on efficiently
  • Low student trust — when feedback visibly produces no action, future submission rates drop sharply
Core Problem: Institutions lack the infrastructure to efficiently listen to students at scale. The volume of feedback exceeds human capacity to review, prioritize, and act on each item in time.

NLP Engine — Upgrade Path

The current engine is a production-quality keyword-weighted rule system. It exports a single function:

analyzeFeedbackText(text, category?, options?)
→ FeedbackAnalysis

This interface can be replaced with a real model without changing any other code in the application:

  • ONNX Runtime Web — run DistilBERT or MiniLM in browser
  • TensorFlow.js — load SavedModel or TFLite
  • Backend API — replace with HTTP call to FastAPI server
Zero vendor lock-in. The entire application works without any cloud subscription or external service.

Slide 06

Automated NLP Analysis Pipeline

NLP Engine

Every submitted feedback text passes through an 8-step analysis pipeline entirely on the client device.

  • 1
    Text NormalizationLowercase conversion, punctuation removal, stopword filtering, tokenization
  • 2
    Language DetectionIdentifies primary language; English-first with extensible language support
  • 3
    Category ScoringWeighted keyword matching across all 8 category dictionaries → argmax selection
  • 4
    Sentiment AnalysisPositive / Neutral / Negative classification with confidence score
  • 5
    Priority EstimationSafety signals, urgency keywords, and time sensitivity — independent of sentiment
  • 6
    Keyword ExtractionTop 3–5 content tokens identified as issue indicators
  • 7
    Summary GenerationConcise one-line summary describing the core issue
  • 8
    Result StorageFull FeedbackAnalysis object saved with processing metadata and timestamps
Average inference time: ~10–15 ms per feedback entry on a standard laptop browser — enabling real-time feedback as students type.
Slide 07

Safety-Aware Priority Estimation

NLP Engine
Key Design Decision: Priority is computed independently from sentiment. A negative tone does NOT automatically mean high priority — and a neutral tone does NOT mean the issue is unimportant.
PriorityTrigger CriteriaExampleResponse Target
CRITICAL Physical safety risk, infrastructure failure, health hazard, credible emergency "Electrical panel sparking in Lab 3" Immediate — within 1 hour
HIGH Multi-day unresolved issues, exam disruption, urgent fee deadlines, service outage "Water supply unavailable for 2 days" Same day
MEDIUM Service degradation, repeated minor complaints, degraded (not absent) service "Wi-Fi is slow in the library" Within 3 days
LOW Suggestions, appreciation, isolated minor observations "Could we get more vending machine options?" Routine queue

Two-Pass Priority Algorithm

Pass 1 — Safety Override
Checks for critical indicator keywords (sparking, injury, poisoning, dangerous, hazard). If found → Priority = Critical, regardless of sentiment score.

Pass 2 — Urgency Scoring
Scores time words (days, urgent, still, deadline), severity amplifiers (completely, never, totally), and unresolved complaint signals to determine High, Medium, or Low.

Slide 12

Human-in-the-Loop Review Workflow

Application Walkthrough
Core Principle: AI predictions are recommendations — not final verdicts. Every classification decision can be reviewed and corrected by authorized staff.

Review Workflow

Staff opens feedback in Feedback Explorer → Detail Drawer opens
↓
Staff reviews AI prediction: Category, Sentiment, Priority, Keywords
↓ Agree or Disagree
Confirm prediction → Mark as reviewed → Assign team → Update status
Correct category / sentiment / priority → Provide reason → Save correction
↓
Correction logged with reviewer ID and timestamp → Feeds into Model Evaluation

Why This Matters

  • Maintains accountability — every decision has an owner
  • Builds a correction dataset for model retraining
  • Prevents automatic closure of Critical issues without human sign-off
  • Provides a full audit trail for institutional compliance

Limitations & Future Roadmap

Evaluation

Current Limitations

  • Rule-based NLP — keyword-weighted scoring, not a trained deep learning model; complex paraphrasing may reduce accuracy
  • English-only — multilingual support (Hindi, regional languages) not yet implemented
  • Browser LocalStorage — suitable for demo and pilot; requires a real database backend for production scale
  • No real-time notifications — escalation alerts are in-app only; email/SMS delivery not configured
  • Evaluation data is illustrative — metrics use labeled demo data, not a real trained model test set

Future Enhancements

  • 🔄 ONNX Transformer Model — integrate DistilBERT or MiniLM for production NLP accuracy
  • 🗄️ Backend API + Database — FastAPI + PostgreSQL for institutional scale
  • 🌐 Multilingual Support — Hindi, regional language classification
  • 📧 Email/SMS Escalations — automated notification on Critical issues
  • 🔐 Role-Based Access Control — Admin, Department Head, Staff tiers
  • 📱 Mobile Student App — dedicated submission interface
  • 🤝 Federated Learning — cross-institution model improvement without sharing raw data

Appendix A

NLP Category Scoring — Technical Detail

Technical

Algorithm

Each feedback text is scored against 8 keyword dictionaries. Each keyword has a weight reflecting its discriminative power for that category.

// For each category C:
score[C] = Σ (keyword_weight × tf(keyword, text))
for all keywords in dictionary[C]

predicted_category = argmax(score)

// Minimum confidence threshold prevents forced assignment
if max(score) < THRESHOLD:
  predicted_category = "General / Uncategorized"

Keyword Dictionary Example — Hostel Category

KeywordWeightRationale
hostel3.0Direct category indicator
water supply2.5Common hostel complaint
mess food2.5Common hostel complaint
warden2.0Hostel-specific role
room1.5Shared with other categories
maintenance1.5Shared with Infrastructure
Appendix B

Priority Heuristics — Technical Detail

Technical

Two-Pass Priority System

Pass 1 — Safety Override Keywords

If any of the following tokens are detected, priority is immediately set to Critical regardless of other scores:

sparking · electrical fire · short circuit · dangerous · hazardous · injury · food poisoning · gas leak · flooding · structural damage · threat · assault · emergency

Pass 2 — Urgency Scoring

Signal TypeExamplesScore Contribution
Time duration wordsdays, weeks, since, still, continuing+2 per match
Urgency amplifiersurgent, immediate, asap, critical+3 per match
Unresolved complaint signalsno response, ignored, not fixed, pending+2 per match
Severity amplifierscompletely, totally, never, always broken+1 per match
Basic necessity absencewater, power, internet unavailable+2 per match

Score ≥ 6 → High | Score 3–5 → Medium | Score < 3 → Low
